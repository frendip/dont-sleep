# Инструкции для работы с Don’t Sleep

## Контекст и карта проекта

- Нативная утилита macOS для работы с закрытой крышкой: Swift Package, AppKit + SwiftUI, без внешних зависимостей. Документация и пользовательские тексты — на русском.
- Начинай с `README.md` и `docs/development.md`; границы компонентов и восстановление описаны в `docs/architecture.md`. При расхождении проверяй исходники и исправляй соответствующую документацию.
- `Sources/DontSleepCore/` — чистый reducer `SessionEngine`, состояния, режимы и питание; не добавляй системный ввод-вывод.
- `Sources/DontSleepPlatform/` — IOKit, ограниченные системные процессы, доверие, защищённый журнал и `WriterLock`.
- `Sources/DontSleepIPC/` — протокол, XPC и `RecoveryRuntime`. Путь команд: App → Controller → Watchdog → системный исполнитель. Только Watchdog меняет сон и владеет журналом; Controller не подменяет его.
- `Sources/DontSleepApp/` — `AppModel` координирует UI на `@MainActor`, `Presentation` вычисляет представление, `NativeStatusMenuController` управляет AppKit-меню, `MenuPanel` — содержимым SwiftUI-окна. UI сам не меняет питание.
- `Tests/` повторяет границы модулей; используй существующие подставные backend/client, управляемое время и временные файлы. `poc/` — отдельный исследовательский прототип, не часть приложения.

## Сборка и проверки

Нужен Mac с Apple Silicon и инструментами Apple. `Package.swift` объявляет tools 5.9 и macOS 13, но компиляция требует SDK с API macOS 26 (`glassEffect`); ветки API сохраняй под проверкой доступности. Release-скрипт собирает ARM64 и подписывает ad-hoc. Проверенные версии инструментов и настройка CI указаны в `docs/development.md` и `.github/workflows/ci.yml`.

Команды из корня репозитория:

```sh
./scripts/test-safe.sh                    # Swift, Python, синтаксис scripts/*.sh и plist
bash -n poc/lid-test.sh                   # дополнительная проверка синтаксиса PoC
./scripts/build-app.sh                    # release; без установки служб
./scripts/verify-bundle.sh "$PWD/dist/Don’t Sleep.app"
'dist/Don’t Sleep.app/Contents/MacOS/DontSleepApp' --smoke-test
```

- Для отдельного Swift-теста: `SDKROOT="$(xcrun --sdk macosx --show-sdk-path)" swift test --filter SessionEngineTests`. Python-набор: `/usr/bin/python3 -m unittest discover -s poc/tests`.
- После изменения кода запускай безопасный набор; при изменениях сборки, ресурсов, установщика или точки входа также собирай bundle и выполняй smoke test. Для правок только документации достаточно сверки фактов, путей и `git diff --check`.
- Отладочный bundle: `DONT_SLEEP_BUILD_CONFIGURATION=debug ./scripts/build-app.sh`. Превью: `'dist/Don’t Sleep.app/Contents/MacOS/DontSleepApp' --render-previews "$PWD/dist/previews"`; они используют тестовые данные и не доказывают корректность живого меню, системных материалов или доступности.
- Установка/удаление служб, реальный запуск `poc/lid-test.sh` и команды изменения питания — отдельные системные операции, не часть обычной сборки или автоматических тестов. Не запускай их для рутинной проверки.

## Условия, которые нужно сохранять

- Выбор режима не запускает сессию; включение выполняется переключателем, активный выбор заблокирован. Новый запуск приложения не возобновляет сессию. Закрытие окна скрывает его; обычный выход проходит через подтверждённое восстановление.
- На аккумуляторе включение разрешено строго выше 20%; при 20% и ниже требуется восстановление. Неизвестное, будущее или старше 5 секунд питание блокирует включение. От сети неизвестный процент допустим, некорректное числовое значение — нет.
- Используй непрерывное монотонное время текущей загрузки ОС, включая сон. Сохраняй проверки идентичности и поколения сессии, чтобы устаревшие ответы не меняли новую сессию.
- Журнал исходного состояния записывается до изменения сна. Незавершённая запись восстанавливается до новых включений; повреждённый журнал нельзя считать отсутствующим. Сохраняй единственного исполнителя и наследование `WriterLock` дочерней командой.
- Успех команды не доказывает восстановление: нужны повторное чтение фактического и сохранённого состояния и надёжная фиксация завершения в журнале. Ошибка, timeout или потеря связи не дают права показать подтверждённое «Выключено» или разрешить новое включение.
- XPC доверяет UID, идентификатору подписанного кода и точному CDHash, а не только bundle ID/PID. Сохраняй проверку версии, размера, nonce, возрастающего sequence и срока запроса. Пересылка не продлевает исходный срок; здоровье Controller не продлевает подтверждение UI.
- `scripts/install-helpers.sh` закреплён SHA-256 в `Sources/DontSleepApp/InstallerProgram.swift`. После изменения установщика сначала проверь привилегированные операции, затем согласованно обнови pin; не обходи проверку ради сборки. После изменения подписанного кода требуется повторная настройка доверия; нельзя смешивать службы и приложение разных сборок.

## Документация, версии и артефакты

- `Resources/Info.plist` — единственный источник версии продукта и номера сборки. Не повышай их при каждой локальной сборке или правке документации. В `0.x` исправления повышают patch, новые возможности/несовместимости — minor; перед распространением изменённой сборки увеличивай номер сборки. IPC версионируется отдельно. Полные правила — `docs/development.md`, пользовательские изменения — `CHANGELOG.md`.
- `docs/validation.md` содержит датированные свидетельства, а не текущий результат тестов. Отделяй свежие автоматические проверки, сообщения пользователя и аппаратные испытания; не переноси старые количества тестов, CDHash или заявления об энергопотреблении на новую сборку. Измерения энергии описаны в `docs/energy.md`.
- Сценарии пользователя — `docs/user-guide.md`; диагностика и штатное удаление — `docs/troubleshooting.md`; правила Git — `docs/repository.md`.
- `.build/`, `dist/`, `.scratch/`, `.local/` и сырые логи остаются локально; `.local/archive/` не является действующей документацией. Системные данные `/Library/Application Support/DontSleep/` не относятся к репозиторию. Сохраняй исходные ресурсы иконки и исполняемые права скриптов; сборка использует `Resources/Assets/AppIcon.icns`.
