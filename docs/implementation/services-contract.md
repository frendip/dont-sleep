# Service contract

Watchdog is the sole actuator, journal owner, and Core SessionEngine host. It holds the protected WriterLock for its entire lifetime; each system child inherits that lock. No controller takeover exists. Controller is an authenticated UI broker and an independent watchdog observer. Its health messages never extend a UI lease. Missing controller health restores the session; missing UI heartbeats restores after 30 seconds. Controller can restart only the fixed watchdog launchd job after bounded health failures. Boot recovery occurs before listening.

`DontSleepIPC.ServiceClient` is an AnyObject protocol with async throwing `status()`, `start(mode: Mode)`, `heartbeat(identity: SessionIdentity)`, `stop()`, returning `ServiceResponse`. `XPCServiceClient()` is the production implementation; its initializer is nonthrowing, trust is loaded when connecting. Response contains Core `snapshot: SessionSnapshot`, `serviceTime: UInt64` (continuous monotonic seconds), `protocolVersion: Int`, and optional durable `lastStopReason: SessionIssue`. UI must discard stale replies, show transport errors, and never infer OFF on timeout. Normal quit waits for `snapshot.verifiedOff` from stop. UI heartbeats originate only from responsive main-thread work, every 5 seconds while active. Selecting a mode calls start and resets duration. No automatic session restart or reconnection start exists.

Transport is Foundation NSXPC with one Data request/reply method, Codable JSON, 16 KiB maximum, protocol version 1, per-connection UUID nonce and strictly increasing sequence. Start carries allowlisted Mode; heartbeat carries SessionIdentity. No remote path, command, original setting, or PID is accepted. Root controller to root watchdog uses a separately authenticated listener and can send health/maintenance plus forwarded UI commands. Application listeners pin exact app cdhash+identifier and authorized UID; all connections pin expected server identity. Protected trust manifest is root-owned under `/Library/Application Support/DontSleep/trust.json`.

Installed labels: `local.dontsleep.controller`, `local.dontsleep.watchdog`. Installed binaries: `/Library/Application Support/DontSleep/bin/DontSleepController`, `DontSleepWatchdog`; the complete `bin/DontSleepApp.app` is the root-protected UI identity copy. UI lives in the user's app bundle but must match the exact installed app pin. Updating requires explicit administrator setup and verified restoration before replacement. No job starts the UI.

Setup receives the live UI cdhash with `APP --uid UID --expected-app-hash CDHASH`. The GUI checks captured installer bytes against a compiled SHA256 digest before authorization and executes that immutable text. Root setup verifies the protected full bundle against the live-app hash before extracting helper pins. Existing helper/trust pairs survive publication as protected backups; interrupted publication is repaired only when both jobs are unloaded, after validating the backup pair. `lockf` on shell-owned descriptor9 serializes setup and removal and releases automatically on process exit; its persistent empty lock file must not be unlinked.

After failed restoration a one-shot 30-second retry deadline is scheduled, including initial boot recovery with no controller. Native power events operate while idle; periodic power fallback and observer health polling are suspended after verified OFF. Last terminal reason is persisted in the recovery record and returned on later UI status, including after daemon/reboot recovery. A new activation clears the prior reason.
