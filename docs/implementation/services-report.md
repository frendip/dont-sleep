# Services implementation report

## Implemented

- Native Foundation NSXPC Data-only protocol with 16 KiB request/reply limits, version 1, per-connection nonce and increasing sequence. Malformed, unsupported-version and replayed requests fail closed. Internal health/maintenance commands are refused on the app-facing listener.
- Both listeners and both connection directions enforce pinned signing requirements. Incoming and reply paths validate effective UID. UI identity is the administrator-selected non-system UID; service peers must be root. Pinning is exact identifier plus cdhash from the protected trust manifest.
- Watchdog is the sole power writer, lifetime WriterLock holder and durable journal owner. Controller brokers UI operations and observes the writer. Controller never issues power writes or acquires the writer lock. Restart uses only the fixed watchdog launchd label through a bounded system command.
- Runtime samples safe power before enable, writes the original snapshot before mutation, verifies apply and restoration, and preserves failed recovery. Every unfinished journal phase restores on startup; it never resumes a previous mode. Failed restoration retries at a 30-second deadline without a UI; explicit stop can retry sooner.
- Controller health is independent of the UI lease and cannot renew it. UI heartbeat requires current session identity. Lease expiry, unsafe power, lost controller guard and mode deadline restore. Native power notifications plus active-only 5-second fallback samples are installed. Both writer and observer periodic timers suspend after verified OFF; one startup observation checks for an existing active writer.
- Setup blocks new starts with a maintenance latch, stops the public broker first, verifies old restoration, then replaces helpers. Removal unregisters jobs only after verified restoration and retains the protected state/trust/binaries for repair. Existing unfinished journals are never deleted.
- Installer serializes setup/removal using a protected advisory setup lock; rejects writable/non-root/symlink protected paths; copies the entire signed app into a protected stage without symlinks or ACLs; verifies strict/deep signature and expected running-app cdhash; derives helper pins only from that verified staged bundle. GUI captures the installer bytes before authorization and binds them to a compiled digest (UI-owned implementation).

## Validation completed

All service tests use temporary private directories and a fake power backend. Recovery tests cover journal-before-write, all unfinished crash phases, failed verification, explicit and automatic retry, controller loss, battery cutoff, stale heartbeats, lease expiry despite health probes, repeated stop, and maintenance start races. Wire tests cover size, version, nonce and sequence rejection. All 12 IPC tests passed after adding durable terminal reason and recovery proof integration. Full Swift test suite was run successfully after integrating the initial service implementation; follow-up complete-suite results are reported by the orchestrator after all agents finish.

A harmless native `lockf` fixture confirmed exclusion while the parent descriptor remained open and reacquisition after parent close. Installer/uninstaller Bash syntax and launchd XML pass local validation. A harmless temporary signed-bundle probe reproduced that copying only an app executable invalidates its Info.plist signature; installer was corrected to retain and verify the full bundle.

No root helper registration, sleep-setting write, system launchctl mutation, or administrator prompt was performed by this implementation task. The only real system power reads belong to the platform feasibility checks.

## Remaining acceptance and limits

Installed Mach-service acceptance/rejection on this host, real process crashes/reboots, physical lid behavior, and energy targets still require supervised acceptance. Tests of the pure runtime plus platform inherited-lock probe are not a claim that those hardware scenarios have passed.

Publication is fail-closed across interrupted updates. Fixed bin and trust publication is not a single filesystem transaction; the prior validated pair remains in protected `previous-bin`/`previous-trust.json`. A subsequent setup repairs an inconsistent pair only when both jobs are unloaded, validates a copy of the retained pair, then performs locked offline recovery before continuing. The journal is never deleted. If backup identity is also invalid or a job is still loaded, repair stops for investigation. The advisory `.setup.lock` file persists but its lock releases on owner exit; never unlink a potentially held lock file. Real interrupted root installation remains a pending acceptance scenario.

Transport replay protection is scoped to one authenticated connection; there is no durable request-history database. Commands are serialized by the writer and UI reconnection never automatically repeats start. Ordinary root users remain outside the protection boundary.

The final complete-suite run during concurrent UI work reported three expected red boundary tests (`testCapturedInstallerPreservesLiteralPathAndCannotExpandShellInput`, `testInstallerRejectsModifiedBytesBeforeProducingRootCommand`, `testSingleInstanceRejectsOtherMatchingAppButIgnoresSelfAndOtherProducts`) while all service/core/platform tests passed. The UI owner was notified and supplied their fixes; the orchestrator must run the final suite on the integrated snapshot. Earlier intermediate fixture failures from Foundation's `/var` symlink were corrected to explicit `/private/tmp`, preserving production anti-symlink checks.

Final verification on 2026-10-10 10:16 (test-log time): all 79 Swift tests passed (22 platform, 12 IPC, 27 core, 18 UI), including the previously red UI boundary cases. Log: `/private/tmp/dontsleep-services-final-tests.log`. The wrapper's post-run `status` assignment was rejected by zsh because it is readonly; the complete Swift output confirms all four test products passed. No test was retried to hide a failure.

If a reboot loads mismatched jobs after an interrupted update, setup refuses automatic repair while they are loaded. Recovery path: under explicit administrator supervision, unload only `system/local.dontsleep.controller` and `system/local.dontsleep.watchdog`, retain all files under the protected installation directory, and rerun the normal UI setup. Setup validates the retained pair and the offline Watchdog must acquire its writer lock and verify recovery before publishing new code. Do not clear the journal or manually reset arbitrary pmset settings.
