# Архитектура и восстановление

Описание текущего кода. Точные типы и сигнатуры определяются исходниками; этот документ фиксирует границы ответственности и основные условия безопасности.

## Компоненты

- `DontSleepCore` — состояния, режимы, питание и чистый reducer `SessionEngine`; без системного ввода-вывода. Время монотонное, в секундах одного запуска ОС, включая сон.
- `DontSleepPlatform` — IOKit, ограниченные системные команды, защищённые файлы, журнал и блокировка единственного исполнителя.
- `DontSleepIPC` — сообщения, XPC, проверка доверия и `RecoveryRuntime`, связывающий ядро с журналом и исполнителем.
- `DontSleepApp` — AppKit-меню в верхней панели и SwiftUI в отдельном окне, представление состояния, настройка и обычный выход. Интерфейс сам не меняет питание.
- `DontSleepController` — привилегированный посредник между UI и Watchdog, наблюдение за его работоспособностью и перезапуск только фиксированной службы.
- `DontSleepWatchdog` — единственный исполнитель изменения сна, владелец журнала и `SessionEngine`. Controller не принимает на себя эту роль.

Путь команды: **App → Controller → Watchdog → системный исполнитель**. Все ответы проходят обратно через Controller. UI запускается вручную; две службы загружаются через LaunchDaemons независимо от него.

## Сессия и питание

Перед включением нужны актуальное питание, готовность служб и подтверждённое отсутствие незавершённого восстановления. На аккумуляторе разрешены 21–100%; от сети допустим неизвестный процент, но некорректное числовое значение отклоняется. Неизвестные, будущие или устаревшие данные питания блокируют включение; предел актуальности — 5 секунд.

UI только запоминает выбор режима; `start` отправляется при включении переключателя. Активный выбор в интерфейсе недоступен. Ядро поддерживает обновление поколения сессии, но это не пользовательский способ переключить работающий таймер. После штатного выключения выбор сохраняется до завершения приложения; новый запуск выбирает «Без таймера» и не возобновляет старую сессию.

Завершение таймера, небезопасное питание, потеря подтверждений UI или Controller переводят сессию в восстановление. Идентификатор сессии и поколение отсекают устаревшие результаты. Смена источника питания сама по себе таймер не сбрасывает.

## Протокол и подтверждение работоспособности

Текущая версия протокола — **2** (`ServiceProtocol.version`). NSXPC переносит Codable JSON через один метод Data request/reply. Максимальный запрос — 16 KiB; у соединения свой nonce и строго возрастающий sequence.

Запрос содержит `issuedAt` и `expiresAt`: срок исполнения не больше **10 секунд**, включая очереди и проверки. Controller сохраняет исходные отметки при пересылке. Watchdog повторно проверяет срок после чтения питания. Старые версии протокола отвергаются.

UI подтверждает работоспособность через отзывчивый основной поток: при скрытом интерфейсе каждые **5 секунд**, при видимом — каждые **4 секунды**, чтобы питание не устаревало на границе опроса. Подтверждение сессии действует до **30 секунд от исходной отправки UI**. Сообщения здоровья Controller не продлевают его. Отсутствие здоровья Controller проверяется отдельно, с порогом 15 секунд при проверке runtime.

Срок подтверждения определяет обнаружение потери UI, а не гарантирует завершение восстановления за 30 секунд. Повторная попытка после ошибки восстановления планируется через 30 секунд. Таймер, обычное выключение и защита по заряду не ждут истечения подтверждения UI.

## Изменение сна и журнал

`PMSetSleepBackend` читает фактический `SleepDisabled` через IOKit и сохранённую настройку через `pmset -g`. До включения обе должны однозначно означать false. Уже отключённый другим способом сон, отсутствующее или неоднозначное значение не принимаются как исходное состояние.

Watchdog записывает исходное состояние до изменения и использует только фиксированную команду `pmset -a disablesleep 1/0`. Успешного кода завершения недостаточно: результат проверяется повторным чтением фактического и сохранённого состояния.

Журнал проходит фазы `prepared`, `active`, `restoring`, `restored`. При старте незавершённая запись обрабатывается до новых включений; таймер и активная сессия не возобновляются. Повреждённый или неизвестный журнал не считается отсутствием сессии. При ошибке записи фазы восстановления попытка вернуть сон допустима только после чтения совпадающего незавершённого журнала; без надёжной фиксации завершения успех не подтверждается.

Единственный Watchdog удерживает `WriterLock`; дочерняя системная команда наследует тот же lock. Задержавшийся процесс не позволяет новому исполнителю писать параллельно. Неподтверждённое завершение дочернего процесса блокирует последующие команды.

## Доверие и установка

XPC проверяет UID, идентификатор подписанного кода и точный CDHash обеих сторон. Bundle ID или PID сами по себе недостаточны. Приложение допускается только для установившего пользователя, службы — для root.

- LaunchDaemons: `local.dontsleep.controller`, `local.dontsleep.watchdog`.
- Данные и доверие: `/Library/Application Support/DontSleep/`, включая `trust.json`, `state/` и защищённые копии кода в `bin/`.
- Пользовательская блокировка экземпляра: `~/Library/Caches/local.dontsleep.app/instance.lock`.

Установщик закреплён SHA-256 в приложении; сборка отклоняет несовпадение. Настройка проверяет защищённую копию bundle и публикует согласованные код и доверие. Обновление и удаление сериализованы и сначала требуют подтверждённого восстановления прежней операции. Для прерванного обновления сохраняются прежние согласованные копии.

«Выключено» в UI означает подтверждение отсутствия незавершённой собственной операции, а не обещание немедленного физического сна Mac. Потеря связи, timeout и перезагрузка не являются доказательством успеха. Границы фактических испытаний перечислены в [статусе проверки](validation.md).
