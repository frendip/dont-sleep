# Разработка

## Требования и структура

Нужен Mac с Apple Silicon и инструментами разработки Apple: `swift`, `xcrun`, macOS SDK, `codesign`, `plutil`; для тестов PoC — `/usr/bin/python3`. Пакет объявляет Swift tools 5.9 и macOS 13 как минимальную платформу, но для компиляции нужен SDK с API macOS 26 (`glassEffect`); проверенное окружение — Xcode 27.0 (27A266a), Apple Swift 6.4, macOS SDK 27.0. Объявленная версия tools не является подтверждённой минимальной версией компилятора. Скрипт выпуска собирает только ARM64. Внешних Swift-пакетов нет. Код Liquid Glass включается на macOS 26+, на более старых версиях используется системный материал.

- `Package.swift` — продукты, цели и тестовые зависимости.
- `Sources/` — ядро, платформенный слой, IPC, приложение и две службы; [архитектура](architecture.md).
- `Tests/` — Swift-тесты состояний, платформы, восстановления и UI.
- `Resources/` — Info.plist, шаблоны LaunchDaemons и исходные/готовые ресурсы иконки.
- `scripts/` — сборка, проверка bundle, тесты, установка и удаление служб.
- `poc/` — исходный исследовательский прототип и его тесты. Он не входит в `.app`.
- `docs/` — актуальные инструкции и статус испытаний.

## Проверки

Из корня проекта:

```sh
./scripts/test-safe.sh
```

Скрипт выбирает SDK через `xcrun`, выполняет `swift test`, `python3 -m unittest discover -s poc/tests`, проверку синтаксиса `scripts/*.sh` и plist. Тесты используют подставные исполнители и временные файлы; процессные тесты запускают безвредные дочерние процессы. Системные службы и настройки питания не меняются.

Для отдельной проверки:

```sh
export SDKROOT="$(xcrun --sdk macosx --show-sdk-path)"
swift test
python3 -m unittest discover -s poc/tests
bash -n poc/lid-test.sh
```

Сам `poc/lid-test.sh` — аппаратный эксперимент с привилегированными операциями, а не обычный тестовый runner. Не запускайте его как часть сборки или параллельно с приложением. Безопасный набор использует его функции с подменёнными системными операциями.

## CI и артефакты

Workflow [`.github/workflows/ci.yml`](../.github/workflows/ci.yml) запускается на всех pull request, push в `main` и вручную через **Actions → CI → Run workflow** (после попадания workflow в `main`). Одна проверка **Build and test (macOS ARM64)** выполняет:

1. Проверку архитектуры и вывод версий Xcode, Swift, SDK и Python.
2. `scripts/test-safe.sh`: Swift- и Python-тесты, синтаксис скриптов и plist; дополнительно `bash -n poc/lid-test.sh`.
3. `scripts/build-app.sh`: release ARM64, ad-hoc подписи и проверку установочного содержимого.
4. `--smoke-test`: запуск точки входа приложения без соединения со службами.
5. Упаковку `.app` с сохранением исполняемых прав и загрузку артефакта.

Используется стандартный ARM64 runner `macos-26` с явно выбранным Xcode 26.6. Доступность версии определяется [образом GitHub](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md); при его обновлении может понадобиться изменить `DEVELOPER_DIR`. Локально проект также проверялся с Xcode 27.0. Проверка в CI не подтверждает поддержку всех Mac и версий macOS.

Workflow имеет только `contents: read`, не требует пользовательских секретов и не сохраняет Git-учётные данные в checkout. Сторонние actions закреплены полными SHA. Новый прогон того же PR или ветки отменяет предыдущий; предел выполнения — 20 минут. Скрипты не устанавливают службы и не меняют питание runner.

Артефакт `dont-sleep-macos-arm64-<commit>` доступен на странице успешного прогона 7 дней. Внутри — `dont-sleep-macos-arm64.tar.gz`; после скачивания внешнего архива Actions распакуйте его, затем выполните:

```sh
tar -xzf dont-sleep-macos-arm64.tar.gz
```

Получится `Don’t Sleep.app`. Предварительная упаковка в tar сохраняет исполняемые права, которые [обычная загрузка файлов артефакта не сохраняет](https://github.com/actions/upload-artifact#permission-loss). Это диагностическая ad-hoc сборка, не нотарифицированный релиз. Для установки действуют обычные правила согласованной сборки и повторной настройки служб.

Зелёный CI подтверждает автоматические проверки. Физическая крышка, реальные отказы установленных служб и энергия остаются отдельными [аппаратными испытаниями](validation.md). Обязательность проверки перед merge настраивается отдельно в правилах защиты `main`.

## Сборка приложения

```sh
./scripts/build-app.sh
```

По умолчанию — release. Для отладочного bundle:

```sh
DONT_SLEEP_BUILD_CONFIGURATION=debug ./scripts/build-app.sh
```

Результат — `dist/Don’t Sleep.app`. Прежний bundle переносится в `dist/.previous/`. Скрипт проверяет SHA-256 установщика, собирает три бинарника, копирует ресурсы, подписывает их ad-hoc и вызывает проверку bundle. Он не регистрирует службы и не меняет питание.

Повторная проверка готовой сборки:

```sh
./scripts/verify-bundle.sh "$PWD/dist/Don’t Sleep.app"
'dist/Don’t Sleep.app/Contents/MacOS/DontSleepApp' --smoke-test
```

`verify-bundle.sh` принимает абсолютный путь; проверяет подписи, идентификаторы, ресурсы и выполняет `--verify-installation-payload` без установки, подключения к службам и системного запроса администратора. Проверки bundle не заменяют тесты кода и аппаратные испытания.

Не обновляйте `InstallerProgram.pinnedSHA256` механически: изменение установщика требует ревью соответствующих привилегированных операций, после чего согласованно обновляются скрипт и его pin. После изменения подписанного кода установленная конфигурация доверия требует повторной настройки через UI.

## Изображения интерфейса и иконка

Готовый бинарник умеет отрисовывать состояния окна из фиксированных данных:

```sh
'dist/Don’t Sleep.app/Contents/MacOS/DontSleepApp' --render-previews "$PWD/dist/previews"
```

Команда создаёт 20 PNG (10 состояний × 2 темы), без клиента служб и изменения питания. Это иллюстрации окна на тестовых данных, не снимки текущего состояния Mac и не изображение верхнего NSMenu. После визуальной проверки в Git можно оставить только нужные изображения в `docs/images/`. В текущем внеэкранном экспорте системные материалы и акцентные цвета могут отличаться от живого окна; тёмный экспорт также показал некорректный цвет части текста. Не используйте эти снимки как доказательство правильности живого оформления или доступности. Для README выбраны только два проверенных светлых состояния.

Для отдельного экспорта иконки из нативного рисунка:

```sh
'dist/Don’t Sleep.app/Contents/MacOS/DontSleepApp' --export-icon "$PWD/dist/icon-export"
```

Получаются PNG, iconset и ICNS; сборка использует закоммиченный `Resources/Assets/AppIcon.icns`. Экспорт в `dist` не заменяет исходные ресурсы автоматически.

## Перед изменением документации

Сверяйте поведение с `AppModel`, `Presentation`, `SessionEngine`, `ServiceMessages` и скриптами. В [статусе проверки](validation.md) отделяйте свежие автоматические результаты, сообщение пользователя и ещё не выполненные аппаратные сценарии. Не выдавайте старые хеши bundle или число тестов за текущие. Правила состава Git описаны [отдельно](repository.md).
